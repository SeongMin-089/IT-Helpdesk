## 2. 권한 및 동작 정책

### 2.1 일반 직원

- 본인이 등록한 문의만 조회하고 관리한다. 타인 문의에 연결된 첨부파일 조회·다운로드는 허용하지 않는다.
- 자신의 문의가 접수(`received`) 상태이고 미배정일 때만 원본 필드 중 허용된 항목을 수정할 수 있다.
- 문의 등록 시 **활성화된 기존 문의 유형** 중 하나를 선택한다. 유형 마스터 레코드를 문의 상세에서 직접 생성하거나 변경할 수 없다.
- 해결(`resolved`)된 본인 문의의 종료 승인 또는 재처리 요청이 가능하다.
- 종료(`closed`)된 문의에는 새 댓글 및 첨부파일을 추가할 수 없다.

### 2.2 IT 담당자

- 전체 문의를 조회하고 수동 배정·처리·해결·재처리를 관리한다.
- 기존 원본 정보 수정 제한을 유지한다. 문의 등록 시 활성 유형을 선택할 수 있으나 저장 후 문의 상세에서 원본 유형을 변경할 수 없다.
- 별도 **설정 → 문의 유형** 화면에서 유형을 관리할 수 있다. 마스터 유형의 이름을 변경하면 해당 유형을 참조하는 여러 문의에 표시되는 이름도 함께 달라진다.
- 종료 문의에 새 댓글이나 첨부파일을 추가할 수 없다.

### 2.3 첨부파일 검사 범위

- Odoo 기본 `ir.attachment`의 모든 사용처를 제한하지 않고 `it.helpdesk.ticket`에 직접 연결되는 파일과 연관 처리 경로를 대상으로 정책을 적용한다.
- 신규 파일 `create()`, 관련 파일의 `write()`/연결 변경과 Chatter 연동 경로를 고려한다.
- 파일 형식 검사에는 확장자와 내용 확인을 함께 적용한다. TXT는 UTF-8 기반 텍스트로 검사하므로 UTF-8이 아닌 일부 레거시 텍스트 인코딩은 허용되지 않을 수 있다.
- UI 제한만이 아니라 서버 측 검증도 실시한다. 단, 실제 브라우저를 통한 모든 우회 경로가 입증되었다는 의미는 아니다.

## 3. Day 4 문제 발견 및 조치 이력

### 3.1 종료 문의 첨부파일 업로드 허용

- **발견:** 종료된 문의에서 Chatter 파일 첨부가 가능했다.
- **조치:** `ir.attachment` 생성 시 연결 문의 상태 검사. 이후 파일 재연결/수정 경로도 검증 범위를 확장했다.
- **확인:** 종료 문의에서 업로드가 차단되고 새로고침 후 파일이 남지 않는 것을 수동 확인했다.

### 3.2 정상 TXT 파일의 업로드 실패

- **발견:** 기존 MIME 추정 결과에 의존한 TXT 검사가 정상 파일을 거부했다.
- **조치:** UTF-8, UTF-8 BOM, 줄바꿈을 고려한 텍스트 검사로 교체하고 일부 바이너리 형식 서명과 제어 문자를 차단했다.
- **확인:** 사용자가 정상 문의에서 `test.txt` 업로드 성공을 수동 확인했다.

### 3.3 문의 유형 마스터 레코드의 의도치 않은 수정

- **발견:** Ticket Form의 관계형 유형 필드를 통해 기존 `HARDWARE` 유형 이름을 `P`로 변경했다. 해당 유형을 참조하는 기존 문의에도 `P`가 표시됐다.
- **조치:** 문의 상세 필드에 `no_create`, `no_create_edit`, `no_open` 옵션 적용. 활성 유형만 선택하도록 도메인 및 서버 검증 보완. 초기 유형 데이터는 `noupdate="1"`로 보호한다.
- **확인:** 기존 유형 이름을 수동 복구하고, 문의 화면에서는 유형 마스터를 직접 편집할 수 없음을 확인했다.
- **유의:** 유형 코드와 연결 문의의 관계는 유지하며 기존 데이터를 자동 변경하지 않았다.

## 4. 검증 기록

### 4.1 자동 테스트

`custom_addons/it_helpdesk/tests/test_day4.py`에 Day 4 관련 **10개 테스트 메서드**가 있으며, Codex의 최종 실행 보고는 **Odoo 로그 기준 12 tests, 실패 0건, 오류 0건**이다. 테스트 메서드 수와 프레임워크 로그에서 집계된 테스트 수는 서로 다를 수 있다.

자동 테스트에는 다음 검증이 포함된다.

- 요청자 지정 제한 및 문의 번호 고유성
- 문의 유형 코드 고유성, 유형 선택 UI 옵션 및 비활성 유형 제한
- 첨부파일 확장자·크기·개수·타인 접근 제한
- 한글 TXT·BOM·CRLF 및 바이너리 위장 거부
- 임시 첨부파일 재연결 및 종료 문의 제한
- 정상 Chatter 첨부, 직접 메시지 생성 우회 방어
- 담당자 배정부터 해결·재처리·종료까지 기존 워크플로 및 History·보관/복원 회귀 검사

> 증거 구분: 자동 테스트 최종 12건 통과 수치는 Codex 실행 보고에 근거한다. GitHub 코드 확인만으로 테스트가 로컬에서 재실행되었다고 간주하지 않는다.
